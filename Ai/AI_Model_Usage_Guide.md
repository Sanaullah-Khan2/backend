# EduAIMS AI Risk Model: Full Usage and Integration Guide

This document provides a comprehensive technical and functional overview of how the **XGBoost ML Model** is utilized in the EduAIMS backend, and how to verify, test, and demonstrate its predictive capabilities to your project supervisor.

---

## 1. Directory Structure & Architecture Overview
The artificial intelligence module is fully encapsulated within the Django backend under the `ai_engine` app.

* **`backend/apps/ai_engine/train_model.py`:** A utility script to re-train the model. It reads the local dataset (`predict+students+dropout+and+academic+success.zip`), maps the extensive 36 features down to the 5 simplified metrics the University uses, and exports the model.
* **`backend/apps/ai_engine/model/xgb_risk_model.pkl`:** The compiled binary of the XGBoost model. 
* **`backend/apps/ai_engine/risk_engine.py`:** The bridge script. It loads the `.pkl` model and provides a simple Python function `calculate_risk_score(...)` to execute predictions.
* **`backend/apps/ai_engine/scoring.py`:** The Django integration layer. It sweeps the SQL database, pulling active students, feeding them into the engine, and permanently saving the predictions to the `RiskScore` table.

## 2. Command Line Demonstration (For Supervisors)
The easiest way to prove the model is analyzing data without deploying the entire frontend is using the test framework.

We created a file called `test_model.py` that mocks five different students (ranging from a perfect honors student to a chronically absent student missing fees). 

**How to Run the Demo:**
1. Open your terminal.
2. Navigate to your backend directory:
   ```bash
   cd "d:\University\FYP\eduAiMS claud\backend"
   ```
3. Run the test script:
   ```bash
   python apps/ai_engine/test_model.py
   ```
**Expected Output:**
The CLI will print out a table of simulated students with their respective AI percentages, their severity tag (🟢 Green / 🟡 Yellow / 🔴 Red), and a string detailing the primary reason for their score (e.g., "Poor attendance").

## 3. Retraining the ML Model (If Dataset Changes)
If your professors or supervisors ask you to tweak the dataset or add new synthetic features, you have a 1-click training script.

**How to Retrain:**
1. Open terminal inside the `backend` folder.
2. Run the training script:
   ```bash
   python apps/ai_engine/train_model.py
   ```
*This script will unzip the dataset, parse the pandas DataFrame, retrain the `XGBClassifier`, update the precision matrix report on screen, and physically overwrite `model/xgb_risk_model.pkl`.*

## 4. How the User Interface Interacts with the Model
Your Next.js frontend seamlessly pulls from the AI Model using authenticated API hooks.

**Admin Perspective (`http://localhost:3000/admin/ai-monitor`)**
* When the Admin navigates to the AI Monitor, a GET request is fired to Django's `api/ai/risk-scores/` endpoint.
* It parses all recent RiskScore objects generated by `scoring.py`.
* The frontend groups these students into analytical charts (identifying how many students are classified under the Red "At-Risk" bracket vs the Green bracket).

**Teacher Perspective (`http://localhost:3000/teacher/dashboard`)**
* The teacher's dashboard only loads AI predictions for students assigned to their specific classrooms.
* If a student's grade average natively drops below a safe margin, the next time the Django Cron jobs run, the AI updates the risk tag to `Yellow` or `Red`.  
* The teacher immediately sees an "AI Alert" pop up on their portal mapping to that specific student, urging them to authorize an intervention (e.g., extending a deadline).

## 5. Integrating with new APIs in the Future
If you need to query the ML model inside any future custom Python files, do not reinvent the wheel. Just import the standalone risk framework:

```python
from apps.ai_engine.risk_engine import calculate_risk_score

score, risk_level, string_reason = calculate_risk_score(
    attendance_pct=55.0,  # Float (0-100)
    grade_avg=60.5,       # Float (0-100)
    grade_trend=-5.0,     # Int
    fee_default=1,        # 1 or 0
    behavior_count=3      # Int (Missed assignments/violations)
)

print(f"Risk: {risk_level} because {string_reason}")
```

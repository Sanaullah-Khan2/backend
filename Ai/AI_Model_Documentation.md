# EduAIMS Machine Learning AI Risk Engine Documentation

## 1. Introduction and Purpose
The EduAIMS AI Risk Engine is an Early Warning Predictive System designed to identify students at risk of academic failure or dropping out. Unlike traditional binary systems (Yes/No), this model utilizes probabilistic classification to generate a highly granular **Risk Score (0–100)**. 

This score is categorized into three actionable levels:
* **GREEN (0-39)**: Safe 
* **YELLOW (40-69)**: Needs monitoring
* **RED (70-100)**: At high risk, immediate intervention required

## 2. Dataset Selection and Feature Engineering
### 2.1 The Base Dataset
The model is trained using the **UCI Student Dropout and Academic Success Dataset**, a highly credible, peer-reviewed dataset containing 36 academic, demographic, and socioeconomic features. 

### 2.2 Feature Engineering (Dimensionality Reduction)
A core challenge in deploying real-world predictive models is ensuring the required input data matches the telemetry practically generated by the software application. The EduAIMS frontend explicitly tracks 5 student metrics. Expecting teachers or administrators to manually input 36 different fields for every single prediction would yield a remarkably poor User Experience (UX) and database bloat.

To resolve this, **Feature Engineering** and **Dimensionality Reduction** were applied:
* **29 exogenous variables** (demographics, personal socio-economics, marital status, nationality) were intentionally dropped. 
* **Why drop them?** This streamlines the user workflow and minimizes demographic bias. The AI strictly adheres to ethical AI practices by judging risk entirely on academic merit and verifiable institutional behaviors, not background.

The remaining 7 raw dataset columns were mathematically merged to synthesize the **5 required macro-features** expected by the EduAIMS platform:

1. **`attendance_pct`**: Derived by calculating the ratio of `Curricular units approved` to `Curricular units enrolled` across both semesters.
2. **`grade_avg`**: Mathematically re-scaled average of the `Curricular units (grade)` from both semesters.
3. **`grade_trend`**: Calculated by subtracting the 1st semester grade from the 2nd semester grade to track the student's trajectory.
4. **`fee_default`**: Synthesized by inverting the raw `Tuition fees up to date` binary flag.
5. **`behavior_count`**: Proxied utilizing the dataset's `Debtor` infractions.

## 3. Model Architecture
### 3.1 Algorithm Initialization
The predictive engine utilizes a **Random Forest Classifier** (`RandomForestClassifier`), selected for its resistance to overfitting and excellent handling of non-linear feature interactions (such as the compounded effect of bad grades *and* low attendance).

**Hyperparameters:**
* `n_estimators = 100`: The model creates an ensemble of 100 independent decision trees.
* `max_depth = 10`: Trees are capped at a limited depth to ensure generalization over outright memorization.
* `class_weight = 'balanced'`: Due to real-world skewing (where most students do not drop out), the loss function penalizes minority class misclassifications heavier to ensure high recall for at-risk students.

### 3.2 Training & Serialization
Data splitting was performed at an 80/20 train/test ratio. Following fitting, the trained classifier, alongside its associated `LabelEncoder`, is serialized utilizing Python's `pickle` library. This compiled binary (`risk_model.pkl`) acts as an entirely decoupled, production-ready microservice module.

## 4. System Integration and Data Flow
The deployment of the model in production is facilitated by `risk_engine.py`, which bridges the machine learning artifacts to the Django backend.

### Real-time Architecture Flow
1. **Request:** The EduAIMS frontend dashboard requests a specific student profile. The Backend queries the database for that student's latest metrics.
2. **AI Invocation:** `risk_engine.calculate_risk_score()` is called with the student's 5 exact metrics passed as arguments.
3. **Probability Mapping:** The pickled classifier is loaded into memory. Instead of forcing a hard rigid classification, `model.predict_proba()` is executed. This returns a soft-max probability array (e.g., 84% likelihood of Dropout, 12% likelihood of stagnant enrollment).
4. **Weighted Aggregation:** The customized Risk Score is mathematically mapped by heavily weighting the Dropout probability and moderately weighting the general Enrolled probability: `Score = (Dropout% * 100) + (Enrolled% * 40)`.
5. **Human Explainability (XAI):** Contextual logic overlays the mathematical result to emit an English "Reason" string (e.g., "Low attendance and dropping grades"), ensuring high model explainability and transparency for teachers.

## 5. Fail-Safe Operations
To ensure high software availability, the production `risk_engine.py` is equipped with an immutable fallback mechanism. If `risk_model.pkl` becomes unreachable, deleted, or corrupted, the system gracefully degrades into a hard-coded, rule-based scoring tier (awarding deterministic penalty points for sub-75% attendance or sub-50% grades), effectively guaranteeing a 100% predictive uptime output.
